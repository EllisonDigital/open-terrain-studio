# v0.3 handoff for Claude

The CPU erosion implementation is isolated on **`v0.3-erosion`**, based on **`f65264a`** (the v0.1 foundation). The original checkout was not edited or switched. Worktree:

```text
../open-terrain-studio-v0.3
```

Finish v0.2 first, then integrate this branch on top of its completed commit. This is an implementation and validation package, not a tagged v0.3 release. No version bump, release tag, remote push or MR has been made. Erosion behaviour and its measured limits are in [erosion.md](erosion.md).

## What is ready

- CPU `simulate.hydraulic` with Height, Flow, Wear, Deposition and Sediment outputs; physical duration and rainfall, rock softness, capacity, deposition, evaporation and downcutting.
- CPU `simulate.thermal` with Height and Debris/Talus outputs; talus angle and duration.
- Spatial strength and hardness inputs on both erosion nodes; `data.rock_hardness` creates horizontal beds.
- Deterministic Rayon passes, in-node progress and cooperative cancellation.
- Tests for mass conservation, identity cases, protected regions, hardness, bit equality across worker counts, mid-simulation cancellation, PNG/EXR masks, saved projects, and 512²/2048² erosion deltas and masks.
- An editable project: [erosion-strata.otstudio](../presets/erosion-strata.otstudio).
- A reproducible release benchmark: `bench_erosion`.
- A Godot integration test exercising all eight outputs, progress and cancellation. The CI smoke jobs run it on both configured Godot versions.

## Changes to reconcile with v0.2

Most implementation is new files under `crates/terrain-nodes/src/erosion/`. Shared-file changes are small, but `terrain-core/src/eval.rs` intentionally overlaps the cache work. A read-only inspection of the v0.2 engine work (now committed as `5681fdf`) on 25 September found `EvalCache`, `EvalOptions.cache`, `EvalOptions.base_dir`, and `EvalContext.base_dir`; the final v0.2 code may differ.

| File | Merge intent |
| --- | --- |
| `terrain-core/src/node.rs` | Add optional `progress` callback to `EvalContext`, initialise to `None`, and keep `with_controls`/`report_progress`. Preserve all v0.2 fields and parameter-driver helpers. `EvalContext::new` keeps its existing signature. |
| `terrain-core/src/eval.rs` | Preserve the v0.2 evaluator and cache. In the **cache-miss** branch, map node fraction to `(node_index + fraction) / total_nodes` and pass it through `ctx.progress`. Check cancellation **before inserting outputs in the cache**. Cache hits still advance normal overall progress. |
| `terrain-nodes/src/lib.rs` | Retain every v0.2 registration; add `pub mod erosion` and register Hydraulic, Thermal, RockHardness. |
| `terrain-nodes/Cargo.toml` | Move the existing Rayon dependency from dev-dependencies to normal dependencies; no version/dependency-lock change. |
| `.gitlab-ci.yml` | Retain v0.2 jobs; add `erosion_test.gd` after the existing Godot smoke test in both Godot-version jobs. |
| `terrain-core/tests/eval_progress.rs` | The two `EvalOptions` struct literals must gain `..Default::default()` for v0.2's added options. Other new evaluation callers already use defaults. |
| `terrain-nodes/tests/erosion.rs` | v0.2 changed `export_node` to accept `&EvalOptions` instead of separate cancellation/progress arguments. Replace the export test's trailing `None, None` with `&EvalOptions::default()`. |

The cache-miss integration should have this shape, adapted to the final evaluator:

```rust
let node_progress = |fraction: f32| {
    if let Some(progress) = opts.progress {
        progress((n as f32 + fraction) / total);
    }
};
ctx.cancel = opts.cancel;
ctx.progress = Some(&node_progress);
// Keep ctx.base_dir and any other v0.2 context setup.
let outputs = kind.evaluate(&ctx)?; // Keep the evaluator's existing error mapping.
if ctx.is_cancelled() {
    return Err(CoreError::Cancelled);
}
// Only now insert the complete Outputs into the cache.
```

`Outputs` contains all ports from one simulation. Previewing Flow after Height should reuse that cache entry. Input mask/hardness changes must invalidate erosion through ordinary graph dependency keys; no erosion-specific cache is needed. Simulation duration, capacity and other parameters already participate in ordinary parameter hashing. The explicit strength port satisfies spatial control without requiring a new parameter-driver API.

The v0.1 UI selects `_first_output` for preview/export. **Retain v0.2's selected-output and marked-output support**, and confirm every new mask appears in its picker and Build tab. Do not replace that editor with the v0.1 files from this branch. No editor or Godot binding implementation files were modified here; the new schemas drive node creation and inspectors.

## Integrating without disturbing either active worktree

After v0.2 is committed, use a third worktree rooted at that commit. Substitute the actual completed v0.2 branch/commit:

```sh
git worktree add ../open-terrain-studio-integration -b integrate-v0.3 <completed-v0.2-commit>
cd ../open-terrain-studio-integration
git merge --no-ff --no-commit v0.3-erosion
# Resolve the shared files using the merge intent above, then run the checks below.
git commit -s
```

Alternatively cherry-pick the branch's commits in order. Do not cherry-pick only the node implementation without the progress API it calls. `git log --reverse --oneline f65264a..v0.3-erosion` lists the integration sequence.

## Verification after integration

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo build -p terrain-godot
godot --headless --path app --script res://tests/smoke_test.gd
godot --headless --path app --script res://tests/erosion_test.gd
cargo run --release -p terrain-nodes --example bench_erosion -- 1024 8 60
```

Also run the v0.2 cache/undo/export/UI checks. Specifically:

1. Load the example, select each erosion output in 2D and as a 3D mask overlay, then export the marked outputs together.
2. Verify switching Height → Flow → Wear reuses the same simulation result; edits to Strength or Rock hardness recompute it, while editing downstream colour/adjustment nodes does not.
3. Cancel during erosion, then request the same graph again: it must finish normally, with no partial result cached and no stale preview delivered.
4. Change duration and mask links, then undo/redo them; check preview, output selections and exports survive save/reload.
5. Compare 512² and 2,048² results on v0.2's alpine, canyon and dune example landforms. The automated fixtures are not a replacement for artist review.

## Checks completed on this branch

- `cargo fmt --all --check` and workspace Clippy with warnings denied: passed.
- `cargo test --workspace`: 40 passed, one pre-existing noise calibration test ignored.
- `cargo build -p terrain-godot`: passed.
- Existing Godot smoke test and new erosion test: passed on both 4.7.2 and 4.6.2.
- 1,024² release benchmark with eight workers: hydraulic 4.666 s, thermal 0.595 s.
- 512²/2,048² tests include both a smooth ridge and a depositing foothill; maximum measured relative height-change RMS error was 1.82%. See the full mask metrics and limits in [erosion.md](erosion.md).

Local diagnostic EXR/PNG files and `overview.png` are in this worktree's ignored `build/erosion-review/` folder. They are not committed golden baselines; the benchmark can regenerate the maps.

## Release review still needed

The measured eight-worker 1,024² hydraulic run is comfortably below 30 seconds on the development laptop, but this is not a pinned eight-core hardware certification. Tests establish same-machine worker-count determinism, not yet byte equality on Windows/macOS or a second CPU. PNG/EXR mask values are checked by round trip, but Unreal material import has not been exercised. Review long runs and rough landforms for stencil bias and small features before declaring the full milestone's visual exit criteria met. GPU work, tiled builds and dynamic subsurface geology remain outside this branch.

The first Godot editor import in the new worktree hit the repository's already-documented GDExtension shutdown crash after import completed. The subsequent real smoke and erosion runs passed; no change to the existing CI import workaround was made.
